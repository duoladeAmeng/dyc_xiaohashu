# 分布式 ID 生成器 - 整体架构概述

## 一、项目定位

本项目是一个**自研的分布式 ID 生成器服务**，核心算法从 CosId 框架迁移而来，采用 **JDBC 作为持久化方案**。项目提供三种 ID 生成策略：

| 策略 | 类名 | 适用场景 | 特点 |
|------|------|----------|------|
| Snowflake | `SnowflakeIdGenerator` | 有序、高性能、时间相关 | 依赖时钟，ID 包含时间信息 |
| Segment | `SegmentIdGenerator` | 数据库号段模式 | 简单可靠，适合中等并发 |
| SegmentChain | `SegmentChainIdGenerator` | 高并发场景 | 链式预取，超高吞吐量 |

## 四、核心设计原则

### 4.1 策略模式

所有 ID 生成器实现统一接口 `IdGenerator`：

```java
public interface IdGenerator {
    long generate();
}
```

### 4.2 模板方法模式

MachineId 分配器使用模板方法：

```
AbstractMachineIdAllocator
├── distribute()           # 模板方法：本地检查 → 远程分配 → 保存状态
│   ├── distributeRemote() # 抽象方法：子类实现
│   ├── revertRemote()     # 抽象方法：子类实现
│   └── guardRemote()      # 抽象方法：子类实现
```

### 4.3 装饰器模式

ClockSync 包装器：

```
ClockSyncSnowflakeIdGenerator (装饰器)
├── actual: SnowflakeIdGenerator (被装饰者)
└── clockBackwardsSynchronizer: ClockBackwardsSynchronizer
```

### 4.4 组合模式

SegmentChain 使用链式结构：

```
IdSegmentChain (链节点)
├── idSegment: IdSegment (实际号段)
├── version: long (版本号)
├── next: IdSegmentChain (下一个节点)
└── 方法: isAvailable(), incrementAndGet(), ensureSetNext()
```

## 五、关键流程概览

### 5.1 Snowflake ID 生成流程

```
调用 generate()
    │
    ├── 1. 获取当前时间戳 (getCurrentTime)
    │
    ├── 2. 检查时钟回拨
    │   └── 如果回拨 → 抛出 ClockBackwardsException
    │
    ├── 3. 检查 sequenceResetThreshold
    │   └── 如果 sequence >= threshold 且时间前进 → 重置 sequence
    │
    ├── 4. 自增 sequence
    │   └── sequence = (sequence + 1) & maxSequence
    │
    ├── 5. 检查 sequence 溢出
    │   └── 如果 sequence == 0 → 调用 nextTime() 等待下一毫秒
    │
    ├── 6. 更新 lastTimestamp
    │
    ├── 7. 检查 timestamp 溢出
    │   └── 如果 diffTimestamp > maxTimestamp → 抛出 TimestampOverflowException
    │
    └── 8. 位拼接返回 ID
        return diffTimestamp << timestampLeft | machineId << machineLeft | sequence
```

### 5.2 Segment ID 生成流程

```
调用 generate()
    │
    ├── [step == 1 特殊路径]
    │   └── 直接调用 nextMaxId() 获取
    │
    └── [step > 1 常规路径]
        │
        ├── 1. Fast Path (无锁)
        │   └── 检查 segment.isAvailable()
        │       └── 是 → segment.incrementAndGet()
        │           └── 未溢出 → 返回
        │
        ├── 2. Slow Path (synchronized)
        │   └── while(true)
        │       ├── 再次检查 segment.isAvailable()
        │       │   └── 是 → 返回
        │       └── 获取新 segment
        │           ├── segmentAllocator.nextIdSegment(ttl)
        │           └── segment = nextSegment
        │
        └── 3. 重复直到成功
```

### 5.3 SegmentChain ID 生成流程

```
调用 generate()
    │
    ├── 1. 遍历链 (headChain → next → ...)
    │   └── 找到可用节点
    │       └── incrementAndGet()
    │           └── 未溢出 → forward() → 返回
    │
    ├── 2. 链耗尽，尝试扩展
    │   └── headChain.trySetNext(preChain -> generateNext(...))
    │       └── 成功 → forward() → 返回
    │
    ├── 3. 发送饥饿信号
    │   └── prefetchJob.hungry()
    │
    └── 4. 重复循环
```

### 5.4 MachineId 分配流程

```
调用 distribute(namespace, machineBit, instanceId, safeGuardDuration)
    │
    ├── 1. 检查本地存储 (MachineStateStorage)
    │   └── 如果存在 → syncUninterruptibly() → 直接返回
    │
    └── 2. 远程分配 (distributeRemote)
        │
        ├── 2.1 distributeBySelf
        │   └── 查询: instance_id = 当前实例 且 last_timestamp > safeGuardAt
        │       └── 找到 → guardRemote() → 返回
        │
        ├── 2.2 distributeByRevert
        │   └── 查询: instance_id = '' 或 last_timestamp <= safeGuardAt
        │       └── 找到 → CAS 更新 → 返回
        │
        └── 2.3 distributeMachine (新建)
            ├── MAX(machine_id) + 1
            ├── INSERT
            └── 如果 duplicate key → 重新分配
```

## 六、数据库设计

### 6.1 cosid_machine 表

```sql
CREATE TABLE cosid_machine (
    name VARCHAR(128) NOT NULL,           -- namespace:machine_id
    namespace VARCHAR(128) NOT NULL,      -- 命名空间
    machine_id INT NOT NULL,              -- 机器 ID
    instance_id VARCHAR(128) NOT NULL,    -- 实例 ID
    last_timestamp BIGINT NOT NULL,       -- 最后时间戳 (high-water mark)
    distribute_time BIGINT NOT NULL,      -- 分配时间
    revert_time BIGINT NOT NULL,          -- 回收时间
    PRIMARY KEY (namespace, machine_id)
);
```

### 6.2 cosid 表

```sql
CREATE TABLE cosid (
    name VARCHAR(128) NOT NULL,           -- 号段名称
    namespace VARCHAR(128) NOT NULL,      -- 命名空间
    last_max_id BIGINT NOT NULL,          -- 最大 ID
    last_fetch_time BIGINT NOT NULL,      -- 最后获取时间
    PRIMARY KEY (namespace, name)
);
```

## 八、性能特性

### 8.1 各策略对比

| 特性 | Snowflake | Segment | SegmentChain |
|------|-----------|---------|--------------|
| QPS | 百万级 | 十万级 | 百万级 |
| 延迟 | 纳秒级 | 毫秒级 | 微秒级 |
| 依赖 | 时钟 | 数据库 | 数据库 |
| 有序性 | 时间有序 | 号段内有序 | 号段内有序 |
| 适用场景 | 一般业务 | 中等并发 | 高并发 |

### 8.2 SegmentChain 优化

- **链式结构**：减少锁竞争
- **异步预取**：提前获取号段
- **动态调整**：根据负载调整预取距离
- **饥饿检测**：自动扩大预取距离

## 九、高可用设计

### 9.1 时钟回拨处理

```
时钟回拨检测
    │
    ├── 回拨 ≤ spinThreshold (1ms)
    │   └── Thread.onSpinWait() 忙等待
    │
    ├── spinThreshold < 回拨 ≤ brokenThreshold (500ms)
    │   └── TimeUnit.sleep(backwards) 睡眠等待
    │
    └── 回拨 > brokenThreshold
        └── 抛出 ClockTooManyBackwardsException
```

### 9.2 MachineId 保护

- **Guard 机制**：定期心跳，防止被回收
- **Stable/Unstable**：实例类型区分
- **High-water mark**：保护 last_timestamp 不被降低

### 9.3 故障恢复

- **重启后**：优先复用已分配的 machineId
- **Instance ID**：基于 IP:PID 自动生成
- **本地缓存**：避免重复分配

## 十、总结

本项目通过从 CosId 迁移核心算法，实现了：

1. **完整的分布式 ID 生成能力**：支持 Snowflake、Segment、SegmentChain 三种策略
2. **JDBC 持久化**：简单可靠的存储方案
3. **Spring Boot 集成**：开箱即用，配置灵活
4. **高可用设计**：时钟回拨处理、MachineId 保护、故障恢复
5. **高性能优化**：SegmentChain 的链式结构和异步预取

核心算法与 CosId 保持完全等价，确保了 ID 生成的正确性和唯一性。
